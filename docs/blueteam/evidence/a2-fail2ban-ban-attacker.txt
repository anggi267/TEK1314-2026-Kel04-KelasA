CATATAN ANALISIS (penting untuk laporan, jangan dihapus)
- Ban bekerja pada layer firewall (nftables, set addr-set-sshd) dan menolak dengan
  `icmp port-unreachable`, sehingga dari attacker terlihat "Connection refused".
- Aturan ban hanya menyasar `tcp dport 2222` (port SSH), jadi port 80 tetap terbuka.
  Ini perilaku standar action fail2ban dengan `port = 2222`: login SSH diblokir,
  layanan web tidak ikut mati. Kalau diinginkan blokir total per-IP, action harus
  diganti (mis. iptables-allports) — catat sebagai opsi hardening lanjutan, bukan bug.
- Deteksi tetap berjalan meski password auth sudah dimatikan (A.1), karena fail2ban
  membaca entri "Invalid user"/"Connection closed ... [preauth]" di journal sshd.
