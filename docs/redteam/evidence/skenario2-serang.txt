RANGKUMAN HASIL (bagian A — perintah panduan apa adanya)
  Hydra v9.7 BERHENTI SEBELUM SATU PUN percobaan password:
    [ERROR] target ssh://192.168.4.5:2222/ does not support password authentication (method reply 4).
  Artinya kontrol A.1 (PasswordAuthentication no) memang mematikan seluruh jalur serangan password.
  KONSEKUENSI PENTING untuk fail2ban: karena tidak ada event autentikasi gagal yang dicatat sshd,
  jail sshd mencatat "Total failed: 0" dan TIDAK ADA IP yang diban. Premis panduan
  ("fail2ban tetap memblokir meski percobaan gagal karena metode auth salah") TIDAK terbukti:
  serangan password tidak pernah sampai ke sshd sama sekali.

RANGKUMAN HASIL (bagian B — uji pengganti: brute-force AKUN, bukan password)
  9 percobaan login dengan user acak (attacker1, fakeuser3, admin5, baduser6, noSuchUser7, zzz8, qqq9, root, …)
  → sshd mencatat "Invalid user …" + "Connection closed by invalid user … [preauth]"
  → fail2ban: Total failed = 8, lalu BANNED 192.168.4.100 setelah melewati maxretry = 5
  → Dari sisi attacker: TCP connect ke 2222 berubah jadi "Connection refused" (109 ms),
    nmap: 2222/tcp filtered (reason port-unreach) = action nftables "reject with icmp port-unreachable".
  → Layanan lain tidak terpengaruh: HTTP 80 tetap 200, MQTT 1883 tetap terbuka
    (ban hanya untuk tcp dport 2222).
  Kesimpulan: kontrol A.1 mematikan jalur password; kontrol A.2 (fail2ban) tetap bekerja,
  tetapi hanya untuk kegagalan berbasis akun/publickey — bukan untuk brute-force password.
